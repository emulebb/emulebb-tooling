# CI-054 - Add native Windows Rust/MFC protocol-parity diagnostics campaign

## Summary

Add a repeatable native-Windows campaign that runs fresh Rust and MFC
diagnostics builds sequentially against equivalent public and deterministic
eD2K/Kad scenarios. The campaign compares packet diagnostics, native packet
captures, state-machine transitions, searches, sharing, and completed downloads
without retaining operator content details in tracked files.

## Intended Shape

- Extend the existing Python capture-then-offline-diff harness and protocol
  oracle instead of adding parallel launch or comparison logic.
- Exercise direct-route UPnP and forced-firewalled cases with isolated profiles,
  campaign-owned firewall rules, managed native captures, and automatic cleanup.
- Load downloads, shares, searches, and forbidden legacy roots exclusively from
  ignored operator-local configuration.
- Build both products freshly through `python -m emule_workspace` and record
  source and executable provenance before live execution.

## Scope Constraints

- Raw packet captures, real titles, searches, hashes, addresses, and
  machine-specific paths remain generated operator-local evidence.
- Completed downloads are verified and compared but never opened or executed.
- Documented Rust omissions remain negative boundary tests, not parity defects.
- Public-network nondeterminism may be inconclusive but must never become a pass.

## Acceptance Criteria

- [ ] Central policy explicitly authorizes the bounded mixed-client exception
      without weakening ordinary direct Rust smoke requirements.
- [ ] The persisted Python harness produces diagnostics dumps and native packet
      captures for Rust and MFC in UPnP and forced-firewalled cases.
- [ ] Every approved download completes for both clients in both cases with
      matching size, eD2K hash, and post-completion SHA-256.
- [ ] Approved shares and filtered server, global-server, and Kad searches are
      exercised without leaking their values into retained summaries.
- [ ] Protocol-oracle and state-machine coverage distinguish parity divergence,
      harness failure, and external inconclusive results.
- [ ] Configured forbidden legacy roots are neither selected nor used by any
      campaign process, profile, incoming directory, log, or capture.
- [ ] Fresh regular and diagnostics builds have source/binary provenance and
      leave no campaign process, mapping, or firewall rule behind.

## Validation

- Tooling taxonomy, structure, policy-static, and GitHub-roadmap checks.
- Focused build-tests unit and mocked orchestration tests.
- Deterministic protocol-oracle and state-machine scenarios.
- Fresh Rust and MFC build matrix followed by the bounded native public campaign.
