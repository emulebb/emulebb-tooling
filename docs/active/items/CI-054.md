# CI-054 - Add native Windows Rust/MFC protocol-parity diagnostics campaign

## Summary

Add a repeatable native-Windows campaign that runs fresh Rust and MFC
diagnostics builds sequentially against equivalent public and deterministic
eD2K/Kad scenarios. The campaign compares packet diagnostics, native packet
captures, state-machine transitions, searches, sharing, and completed downloads
without retaining operator content details in tracked files.

## Intended Shape

- Extend the existing Python capture-then-offline-diff harness and protocol
  oracle instead of adding parallel launch or comparison logic.
- Exercise direct-route UPnP and forced-firewalled cases with isolated profiles,
  campaign-owned firewall rules, managed native captures, and automatic cleanup.
- Load downloads, shares, searches, and forbidden legacy roots exclusively from
  ignored operator-local configuration.
- Build both products freshly through `python -m emule_workspace` and record
  source and executable provenance before live execution.

## Scope Constraints

- Raw packet captures, real titles, searches, hashes, addresses, and
  machine-specific paths remain generated operator-local evidence.
- Completed downloads are verified and compared but never opened or executed.
- Documented Rust omissions remain negative boundary tests, not parity defects.
- Public-network nondeterminism may be inconclusive but must never become a pass.

## Deterministic Source Lifecycle Slice

The first bounded vertical slice is the local-server source lifecycle:

1. connect and complete login/ID assignment;
2. publish one exact file;
3. request and observe the publisher as a source;
4. disconnect the publisher and observe source withdrawal;
5. reconnect the same profile and republish the same file; and
6. request the source again and complete the transfer.

This slice is deliberately narrower than the full wire campaign. It proves the
shared session/index invariant before adding Kad, public-network routing,
compression combinations, or broad callback coverage.

### Reference Baseline

The 2026-10-20 source review used:

- official aMule `6b0500cb743a361cb8c1b4f3df713524064dfb06`;
- stock eMule 0.72a `ac3d52eafd88e9f6d9e0c2204c6dbead18db750b`;
- Lugdunum eServer 17.15 decompiled control flow as a read-only historical
  server reference; and
- the managed Rust `ed2k-server` fork at the exact revision recorded by each
  retained run.

Stock eMule and aMule share the core sequence and wire messages:

- `OP_LOGINREQUEST` (`0x01`) followed by `OP_IDCHANGE` (`0x40`);
- `OP_OFFERFILES` (`0x15`) for publication;
- `OP_GETSOURCES` / `OP_GETSOURCES_OBFU` (`0x19` / `0x23`); and
- `OP_FOUNDSOURCES` / `OP_FOUNDSOURCES_OBFU` (`0x42` / `0x44`).

Neither client sends an explicit unpublish message when its server socket
closes. Source lifetime is owned by the server session. Lugdunum marks the
session disconnected immediately and removes its publications through a
deferred cleanup worker. The Rust server removes the disconnected session's
sources synchronously, while guarding a newer replacement session with the
same user hash from stale teardown. The campaign therefore asserts eventual
withdrawal, not a hardcoded cleanup delay.

### Timing Contract

- Stock eMule republishes immediately after reaching the connected state.
- aMule clears publication state on reconnect but may wait for the remainder of
  its 60-second publication gate. Its lane gets a bounded 75-second republish
  budget and reports the measured delay.
- eMuleBB MFC follows the stock lane unless diagnostics prove an intentional
  maintained divergence.
- Rust must publish within its explicit deterministic harness timeout; it does
  not inherit the aMule delay allowance.
- The initial source request is tested. The periodic reask difference (800
  seconds in aMule and 900 seconds in stock eMule) is recorded but not slept
  through in this slice.

### State And Evidence Contract

Each client lane records the same ordered states:

1. `connected`: the server observes the named client after ID assignment;
2. `published`: the exact hash, size, endpoint, completeness flag, and user hash
   are observable;
3. `served`: a distinct consumer obtains the endpoint and persists it as a
   transfer source;
4. `withdrawn`: the publisher session and its exact endpoint are absent;
5. `reconnected`: the same isolated profile establishes a new session;
6. `republished`: the exact endpoint returns without duplicate source count;
7. `completed`: the consumer completes with matching size, eD2K hash, and
   SHA-256.

The fixed-stock, moving-aMule, MFC-diagnostics, and Rust lanes remain separate
rows in retained evidence. A missing executable or adapter is `not-run`, never
an implicit pass. Lugdunum remains a source-level reference only and is not
executed by the campaign.

### Required Negative Checks

- A same-session re-offer must refresh or deduplicate the source, not increment
  availability.
- A source request must not return the requester itself.
- The same hash with the wrong size must not resolve to the published source.
- A disconnected endpoint must stop being served even when another source
  keeps the file indexed.
- Rapid reconnect must converge to one live source; stale-session cleanup must
  not remove the replacement session's publication.
- A zero-source result is observed by bounded absence or state inspection; the
  harness must not require an explicit empty `OP_FOUNDSOURCES` reply.

### Evidence Snapshot - 2026-10-20

The retained deterministic executions used build-tests commits `01dfa71`,
`a8f3f0e`, `8525558`, and `0d4a65c`, Rust server revision
`784cc76fb49800f8b1429857fa62db4131fe1d71`, and a 138,412,032-byte generated
fixture. Raw evidence remains below the configured workspace output root.

- eMuleBB MFC diagnostics passed in `source-lifecycle-mfc-r2` through
  connect, publish, source observation, exact endpoint withdrawal, reconnect,
  single-source republish, and completed transfer.
- Fixed stock eMule 0.72a passed the same scope in
  `source-lifecycle-stock-r3`.
- Official aMule `6b0500cb743a361cb8c1b4f3df713524064dfb06` passed the
  same scope in `source-lifecycle-amule-r4`. Its delayed republish completed in
  62.687 seconds, inside the lane-specific 75-second allowance, and converged
  to one source.
- eMuleBB Rust passed in `source-lifecycle-rust-r6`. The exact client and source
  endpoint withdrew, the same persisted profile republished one complete source
  in 2.725 seconds, and MFC completed the 138,412,032-byte transfer with
  SHA-256 `921c8eb7ebd462359cde8cb0ce89a8563d868391774886f099f800dd4990ac1a`.

All three completed runs produced the same fixture SHA-256,
`2d160a7292833466cb5a2693ced8ea754592be16cc9d87b8eee7f4e7978db7c3`.
The stock lane required one inert fixed-baseline startup seam, commit
`f808d546`, so `-c` selects a campaign-owned profile root before preferences
are loaded. The seam does not change default startup or protocol behavior.
The aMule lane used the staged upstream runtime built from an output-root
worktree by build orchestration commit `b254130`; the canonical upstream clone
remained clean.

These four passes prove the shared server-session lifecycle for MFC, fixed
stock eMule, current upstream aMule, and eMuleBB Rust. They do not yet close the
public-network campaign or the remaining same-session, self-exclusion,
wrong-size, and rapid replacement-session negative cases.

## Acceptance Criteria

- [ ] Central policy explicitly authorizes the bounded mixed-client exception
      without weakening ordinary direct Rust smoke requirements.
- [ ] The persisted Python harness produces diagnostics dumps and native packet
      captures for Rust and MFC in UPnP and forced-firewalled cases.
- [ ] Every approved download completes for both clients in both cases with
      matching size, eD2K hash, and post-completion SHA-256.
- [ ] Approved shares and filtered server, global-server, and Kad searches are
      exercised without leaking their values into retained summaries.
- [ ] Protocol-oracle and state-machine coverage distinguish parity divergence,
      harness failure, and external inconclusive results.
- [ ] Configured forbidden legacy roots are neither selected nor used by any
      campaign process, profile, incoming directory, log, or capture.
- [ ] Fresh regular and diagnostics builds have source/binary provenance and
      leave no campaign process, mapping, or firewall rule behind.
- [x] The deterministic source-lifecycle slice records all seven ordered states
      for MFC diagnostics, stock eMule, official aMule, and Rust.
- [x] Disconnect removes the exact publisher endpoint without requiring the
      entire file record to disappear.
- [x] Reconnect/republish converges to one source within the lane-specific time
      budget and a subsequent transfer completes with identical content.
- [ ] Same-session republish, requester self-exclusion, wrong-size lookup, and
      rapid reconnect are retained negative checks.
