# eD2K Forums And Sites Inventory

Last verified: 2026-06-07

This inventory tracks language-specific eMule, eD2K, P2P, and adjacent
technical forums, mod sites, bootstrap services, news pages, and archive
references that are useful for eD2K/eMule research or eMuleBB outreach.

It is a research index, not an endorsement list. Before posting, review each
community's rules, moderator expectations, and tolerance for open-source fork
announcements. Do not post copyrighted content, ED2K content links, or piracy
framing. Outreach posts should present eMuleBB as an open-source Windows eMule
product/fork with stock-compatible eD2K/Kad behavior, public source, docs, and
release/nightly builds.

## Search Visibility Actions

- Keep `https://emulebb.github.io/` as the canonical landing page in every
  announcement.
- Use search-friendly title words that users still type: `eMule`, `eMuleBB`,
  `Windows 11`, `VPN/interface binding`, `upload slots`, `Kad`, `REST API`,
  `0.7.3-rc.1`, and `nightly builds`.
- Submit the org site sitemap to Google Search Console and Bing Webmaster Tools.
- Publish GitHub Releases with exact version text in the title, for example
  `eMuleBB 0.7.3-rc.1`.
- Add one public comparison page later for "eMuleBB vs eMule Community vs aMule"
  with careful wording: eMuleBB is not a protocol fork.
- Localize short announcement posts for the strongest languages instead of
  posting English everywhere.
- Ask moderators first where the forum is small, old, or strict.

## Announcement Template Checklist

Every post should include:

- one-line project identity: eMuleBB is eMule broadband edition
- source link: `https://github.com/emulebb/emulebb`
- public site link: `https://emulebb.github.io/`
- rendered docs link: `https://emulebb.github.io/emulebb-tooling/`
- release/nightly link: `https://github.com/emulebb/emulebb/releases`
- practical value: VPN/interface binding, upload-slot control, large-library
  work, REST/API automation, release proof
- compatibility note: stock-compatible eD2K/Kad behavior remains the default
- support request: testers should use backed-up or disposable profiles and
  report crashes, freezes, package issues, REST/controller problems, and real
  network regressions

## Announcement Positioning

Use this posture consistently:

- eMuleBB is the product name; "eMule broadband edition" is the descriptive
  expansion.
- eMuleBB is a maintained Windows eMule fork/product, not a protocol fork.
- `0.7.3-rc.1` is the planned release candidate; do not call it released until
  the release docs and tag say so.
- Nightlies are available for public testing.
- The project preserves compatibility where eD2K/Kad behavior matters, while
  improving local operation around broadband upload, binding, large libraries,
  REST automation, packaging, and test evidence.

## Avoid

- Do not advertise copyrighted downloads, content discovery, or ED2K links.
- Do not promise anonymity, VPN leak prevention, or a built-in VPN kill switch.
  eMuleBB supports explicit binding; route enforcement remains external.
- Do not imply eMuleBB replaces aMule or eMule Community for every user.
- Do not post long changelog dumps as a first message. Link docs and releases
  instead.
- Do not translate technical terms inconsistently. Preserve `eMuleBB`, `eMule`,
  `eD2K`, `Kad`, `REST`, `WebServer`, `VPN/interface binding`, `UPnP/NAT`,
  `0.7.3-rc.1`, and repository names.
